### 3. 默认 limit 取值理由

| 接口 | 演示账号实有数据 | 内容 |
|---|---|---|
| `/api/doctors` | 19 条 | 全部医生（`dept_id` 分科时最多 3~4 条） |
| `/api/coupons` | 4 条（可用 3 + 已失效 1）+ 券中心 4 个模板 | 我的券 + 领券中心 |
| `/api/addresses` | 11 条（uid=1） | 收货地址 |

三张表存量数据均 **远小于 100**。因此：

- 后端默认值取 `limit = 100`，即 `paging()` 的夹紧上限（`min(100, limit)`）。这是「不破坏现有完整展示」的安全边界：不传参时 `limit=100` 已覆盖全量，`has_more` 恒为 `False`，返回条数与改造前逐条一致（见验收 a）。
- 前端显式传 `limit=20` 并配合触底加载：首屏量与改造前（11~19 条）持平或更小，滚动后自动补齐，数据增长到超过 20 条时也能持续加载，不会出现「只能看前 20 条」的截断。
- 若后续数据量突破 100，未升级的前端调用方（不传参）会被 `limit=100` 截断——已在报告「遗留观察」中登记，需要时可改为 `has_more` 驱动的显式翻页。

## 三、两处遗留风险的判断与建议方案

### 风险一：`/api/register` 对已注册手机号返回「该手机号已注册」（`app.py` 774–775）

```python
if q("SELECT id FROM users WHERE phone=?", (phone,), one=True):
    return {"ok": False, "msg": "该手机号已注册"}
```

**判断**：枚举通道仍在，但成本已被抬高——第三批加固后 `/api/sms/code` 对已注册/未注册号返回完全一致且都给码，攻击者必须先拿到有效验证码才能走到这一分支；而拿码受「同号 60 秒冷却 + 同 IP 5 次/分钟」双重限制。即：**从「零成本探测」降级为「每条手机号一次短信 + 限流成本」**，属中低风险，可接受但不理想。

**建议方案**（按落地成本排序）：

1. **文案去特征化（最小改动）**：把该分支改为通用文案，例如 `{"ok": False, "msg": "该手机号暂无法完成注册，请直接登录或找回密码"}`。密码找回入口本身对已注册/未注册也应有统一响应，否则风险只是被搬到找回密码流程。
2. **注册即登录引导（推荐）**：已注册号走「验证码已通过，请使用验证码登录」静默引导——因为此刻验证码已被验证通过，等价于一次合法的免密登录；对真实老用户是完全正向的体验优化，对攻击者则拿不到任何额外信号（都是「请登录」）。
3. **改造为验证码登录/注册一体接口**：`/api/login-by-sms` 与 `/api/register` 合并语义，服务端按手机号是否存在自动分流，前端只表现「进入」一个结果。这是根治方案，但涉及前端 Register/Login 两页合并，工作量最大。

**当前处置**：本轮按要求不改代码，仅登记。若只做一次改动，建议选方案 2。

### 风险二：`/api/sms/code` 响应体明文回显 `code`（`app.py` 759）

```python
return {"ok": True, "code": code, "msg": "验证码已发送，请注意查收"}
```

**判断**：这在本地演示环境是为「无短信网关也能跑通注册/登录」刻意为之，但在生产等价于**验证码公开泄露**——任何人只要知道手机号即可直接拿到码完成注册或验证码登录，绕过全部短信归属校验。这是本轮三处加固里**风险等级最高**的一项（高），必须在真实上线前处理。

**建议方案**：

1. **配置开关（一步到位的最小方案）**：新增 `SMS_ECHO_CODE = os.getenv("SMS_ECHO_CODE", "0") == "1"`，回显字段放在 `if SMS_ECHO_CODE:` 分支内。本地/演示环境在 `.env` 打开，生产默认关闭；配合前端「无回显时走真实短信」的既有逻辑即可，零接口契约破坏。
2. **接入真实短信网关**：替换 `SMS_CODE[phone] = (code, exp)` 的生成处，回显字段彻底删除；日志侧只记录 `phone` 掩码与 code 的 hash，不落明文（当前 `core.log` 若记录 code 也需一并脱敏）。
3. **过渡期白名单**：在方案 1 基础上再加来源限制——仅 `127.0.0.1` / 内网白名单 IP 才回显，公网请求一律不回显。适合「演示环境也要对外可访问」的场景。

**当前处置**：本轮按要求不改代码，仅登记。上线前必须落地方案 1 或 2。
