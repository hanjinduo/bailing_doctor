## 三、遗留风险与说明

1. **登录失败语义由 200 改为 401**：前端 axios 拦截器对 401 会清本地 token 并提示后端 msg，登录页本身无 token 可清，影响可控；`Login.vue` 已补 `catch` 避免未捕获异常。若后续有第三方客户端依赖「HTTP 200 + ok:false」判定登录失败，需同步调整。
2. **旧格式哈希仍保留兼容分支**：为不中断存量用户登录，`_legacy_hash` 长期存在；只要库中存在未迁移用户，`sha256("bailing"+pwd)` 的弱算法事实仍存在（仅在校验时）。建议后续增加「登录 N 次后强制改密」或批量迁移任务，最终删除兼容分支。
3. **token 版本号机制使登出即时生效，但 token 无法单点吊销**：`token_ver` 为整用户粒度，任一终端登出会使该用户所有在线终端一起掉线（符合本轮需求，但多端场景体验上偏严格）。
4. **`/api/sms/code` 在演示环境仍回显 `code` 字段**：为保证演示体验保留（本轮只做枚举防护）；生产环境应删除该字段并通过真实短信通道下发。
5. **验证码与冷却存于进程内存**：`SMS_CODE/SMS_LAST` 重启即丢失，多进程/多实例部署下冷却与限流不共享，需引入 Redis 等共享存储。
6. **限流 sweep 为惰性触发**：仅在 `allow()` 持续被调用时推进；若服务长时间零流量，过期 key 会滞留内存直到下一次请求（量级可控，不影响正确性）。
7. **历史自测残留**：`chats` 表仍存在少量更早轮次自测产生的记录（id 48/49 等，2026-11-18 16:0x），与本轮无关，未做清理以免误删演示数据；如需一并清理可另行确认。
8. **`.env` 未触碰**，`JWT_SECRET` 仍由环境变量注入；本轮未改动任何接口字段名与返回结构（除登录失败状态码，见第 1 条）。
