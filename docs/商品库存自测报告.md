# 商品库存能力自测报告

日期：2026-11-21　环境：MySQL 8.0（默认引擎）+ FastAPI 127.0.0.1:8010 + Vue3/Vant 前端

## 一、本轮修的缺陷

| 编号 | 缺陷 | 性质 |
| --- | --- | --- |
| S-1 | 前端商品详情用「默认分页 20 条的列表」本地 `find` 商品，id 靠后（21 以后）的商品点开为空 | 功能不可用（演示会点到） |
| S-2 | 全站无库存概念：售罄商品可无限加购、可下单，支付必然成功 | 业务不真实，面试必被追问 |
| S-3 | 无库存即无并发扣减，重复/并发支付无「不超卖」保证 | 资金类一致性缺口 |
| S-4 | 退款只改订单状态，库存与销量不回收（退款越多库存越少） | 引入库存后的新增闭环缺口 |
| S-5 | 7 个详情页只在 `onMounted` 拉数据、未监听路由参数：从 A 详情跳到同路由的 B 详情时组件实例复用，页面仍显示 A 的内容（商品连点两个商品、消息连点两个会话都会串数据） | 前端真实错乱，演示易被撞见 |

## 二、实现要点

### 后端（app.py）

1. `meds` 表新增 `stock INT DEFAULT NULL`，并纳入 `MIGRATE_COLS["meds"]`：旧库启动自动补列，无需重建表。
2. 库存口径函数：
   - `stock_of(m)`：`NULL` 或负值视为「不限库存」（老数据/服务类商品不受影响）；
   - `out_of_stock(m, qty)`：判断是否不足。
3. 启动幂等初始化：仅对 `stock IS NULL` 的行填充差异化库存（30~130），并周期性制造「售罄（0）」与「紧张（4）」两类演示态，便于面试现场展示。
4. 新增 `GET /api/meds/{id}` 单查接口，返回 `stock` / `stock_note` / `tips`；不存在统一中文提示（修 S-1）。
5. 库存校验三处前置：加购累计校验、改量目标值校验、下单前逐项预检（都返回中文「库存不足，仅剩 N 件」/「已售罄」）。
6. 支付期强一致：`order_pay` 事务内用条件更新
   `UPDATE meds SET stock=stock-?, sales=sales+? WHERE id=? AND stock>=?`，
   `rowcount=0` 且商品为限库存时抛错并整体回滚——并发双击不会超卖、不会重复累加销量、不会重复写通知。
7. 退款闭环（修 S-4）：`order_refund` 改为事务，状态迁移用
   `UPDATE ... WHERE status IN ('待发货','已发货')` + `rowcount` 判定，重复退款被拒；
   同事务内按订单 items 回补库存（`CASE WHEN stock IS NULL` 保持不限库存语义）、回退销量（不低于 0），再写通知。

### 前端

- `Product.vue`：改调单查接口；展示库存文案（售罄红 / 仅剩 N 件橙）、数量加减受库存约束、售罄时按钮禁用并显示「已售罄」。
- `Shop.vue`：列表卡片展示库存小字，「加入购物车」在售罄时禁用。
- `Cart.vue`：条目提示售罄 / 超出库存，`+` 在达上限时禁用。
- 详情页参数监听（修 S-5）：`Product.vue`、`Pkg.vue`、`Rx.vue`、`NewsDetail.vue`、`Doctor.vue`、`Chat.vue`、`PayChat.vue`
  统一改为「`load()` 抽函数 + `onMounted(load)` + `watch(路由参数, load)`」，
  `Chat.vue` / `PayChat.vue` 的会话 id 由固定值改为 `computed`；
  跨详情切换时先清空旧状态（消息、处方、计时、输入框、优惠券）再重新拉取，避免串数据。

## 六、遗留与说明

- 库存为单仓模拟，未做多仓/锁定库存（下单即预检、支付才实扣，超时未支付不占库存）。
- 商品不存在时返回中文提示而非严格 404 状态码，与前序接口口径一致。
- 数据库中仍有历史遗留的孤儿数据（`user_id` 指向已不存在用户的订单/会话/通知/购物车/地址/优惠券），属早期测试用户删除后未级联清理，不影响演示账号；如需清理需另行确认。
