## 三、遗留与风险

1. **前端未加 `accept` 限制**：`frontend\src\views\Records.vue` 的 `<input type="file">` 未设 `accept`，用户仍可选任意文件，被拒后由后端 400 文案提示。属体验问题，非安全问题；本轮按“不改其他行为”未改前端（改则需重新构建，留待后续）。
2. **已有历史文件不受影响**：`/uploads` 扩展名收口只拦截请求，不删除既有文件；库中历史记录若指向非白名单扩展名文件，将变为不可直接访问，需通过 `/api/record/file/{rid}`（FileResponse）走。当前库中无此类记录。
3. **下载路径未变**：`/api/record/file/{rid}` 仍以 `FileResponse(filename=records.name)` 返回，`Content-Disposition: attachment` + 全局 nosniff 已足够防内联执行，未做额外改造。
4. **`records.name` 仍可能含特殊字符**：只做了 basename 提取与 120 字截断，未做全字符白名单，若后续要回显到 HTML 需前端确保转义（Vue 默认文本插值即转义）。
5. **CSP 未在浏览器端做渲染断言**：本环境仅做 HTTP 层与构建产物静态核对（同源、无内联脚本、无外链），如需 100% 确认可在浏览器打开首页查看控制台无 CSP 报错。
6. **HSTS 依赖反代头**：`X-Forwarded-Proto` 由前置代理设置，直连 http 下不添加 HSTS，符合本地开发不被缓存污染的要求；上线后由反代补该头即可生效。
